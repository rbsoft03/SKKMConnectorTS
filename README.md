# SkkmConnectorTS

`TypeScript`-библиотека для работы с **Сервером ККМ**
из приложений на TypeScript/JavaScript. Даёт класс `ServerKkm`: свойства на
вход, методы на действие, свойства на выход — вместо ручных HTTP-запросов
к серверу печати.

> Полный перечень операций, полей и значений — в документации API (см. [Полный API](#полный-api))

## Возможности

- **Полное покрытие REST API Сервера ККМ 4.0** — печать чеков, возвраты и коррекции,
  открытие и закрытие смены, X/Z-отчёты и отчёт о расчётах, внесение и выемка
  наличных, слипы, картинки, маркировка, фискализация, очередь печати, шаблоны,
  операции, а также администрирование (пользователи, настройки службы, пулы,
  добавление и изменение ККТ).
- **Простой доступ** — один объект `ServerKkm`: заполняете свойства, вызываете
  метод, читаете результат из свойств — без ручной сборки HTTP-запросов и без
  `fetch` в коде приложения.
- **Синхронный и асинхронный режим** — ждать выполнение на кассе или поставить
  задание в очередь и опросить статус позже.
- **Состояние касс** — список устройств с сервера, сведения о ККТ, статус смены,
  счётчики, остаток наличных.
- **Работает и в браузере, и в Node.js** — транспорт построен на стандартном
  `fetch`/`AbortController`, без зависимостей от файловой системы или других
  Node-специфичных API.


## Требования

- **Node.js 18+** — для встроенного `fetch`; в браузере современный движок
  с поддержкой `fetch`/`AbortController` подходит без дополнительных настроек.
- **TypeScript 5+** (не обязателен) — библиотека поставляется с `.d.ts`,
  можно подключать и из чистого JavaScript.
- **Доступный Сервер ККМ 4.0** — адрес и порт службы печати; если на сервере
  выключен анонимный доступ — токен авторизации.

## Установка

Коннектор подключают двумя путями: **npm-пакетом из `.tgz`** (обычная
интеграция) или **относительной ссылкой на исходники** (когда коннектор лежит
рядом и правится вместе с приложением). Код использования везде один: пакет
`skkmconnectorts`, класс `ServerKkm`.

### npm-пакет из `.tgz`

Пакет `skkmconnectorts` ставится локально из файла `.tgz` — npm поддерживает
путь к архиву прямо как источник зависимости.

**У вас готовая версия.** В репозитории уже лежит собранный
`skkmconnectorts-1.0.0.tgz`. Установите его напрямую по пути к файлу:

```bash
npm install /путь/к/skkmconnectorts-1.0.0.tgz
```

Здесь указывается путь к **самому файлу** `.tgz`, а не к папке.

**Вы изменили исходный код.** Сначала соберите и упакуйте — `npm pack` создаст
файл `skkmconnectorts-<версия>.tgz` в текущей папке:

```bash
cd skkmconnectorts
npm run build
npm pack
```

Затем установите собранный пакет тем же способом, что и готовый:

```bash
npm install /путь/к/skkmconnectorts/skkmconnectorts-1.0.0.tgz
```

После установки в `package.json` приложения появится запись:

```json
"dependencies": {
  "skkmconnectorts": "file:../skkmconnectorts/skkmconnectorts-1.0.0.tgz"
}
```

### Ссылка на исходники (npm link / file:)

Для разработки коннектора и приложения одновременно удобнее сослаться прямо
на папку с исходниками, без пересборки `.tgz` на каждое изменение:

```json
"dependencies": {
  "skkmconnectorts": "file:../skkmconnectorts"
}
```

```bash
npm install
```

При такой ссылке npm подхватывает `dist/` из папки коннектора — после правок
в `src/` не забывайте `npm run build` в папке коннектора, иначе приложение
продолжит видеть старую сборку.

Для поставки клиенту обычно берут `.tgz`-пакет (или публикацию в приватный
npm-реестр); для доработки самой библиотеки удобнее ссылка на исходники.


## Как открыть и собрать в VS Code

### Шаг 1 — установи Node.js и VS Code

Скачай [Node.js 18+](https://nodejs.org/) и [VS Code](https://code.visualstudio.com/).
Проверь версию:

```bash
node --version
```

### Шаг 2 — открой папку

**File → Open Folder** → папка `skkmconnectorts` (там, где `package.json`).
VS Code сам предложит установить рекомендованные расширения TypeScript, если
они есть в `.vscode/extensions.json`.

### Шаг 3 — поставь зависимости и собери

Во встроенном терминале (`` Ctrl+` ``):

```bash
npm install
npm run build
```

`npm run build` запускает `tsc` — компилятор проверит типы и сложит `.js`/`.d.ts`
в `dist/`. Это библиотека: отдельного «запуска» нет — подключай пакет к своему
приложению и запускай уже его.

### Частые проблемы

- **Ошибки про недостающие типы сразу после клонирования** — `rm -rf dist && npm run build`
- **`npm install` не может найти пакет `skkmconnectorts`** — проверь, что путь
  в `file:` совпадает с реальным расположением папки/архива, и что там уже
  выполнен `npm run build` (иначе `dist/` пуст)
- **IntelliSense не видит типы после правок в `src/`** — `Ctrl+Shift+P` →
  **TypeScript: Restart TS Server**

## Как устроен коннектор

Один экземпляр `ServerKkm` — одна рабочая сессия.

1. Задайте подключение: адрес, токен, имя кассы, кассира.
2. Перед новым чеком вызовите `NewRequest()` — очистятся позиции, оплаты,
   покупатель и коррекция. Подключение и кассир останутся.
3. Заполните свойства под операцию.
4. Вызовите метод (`await`).
5. Проверьте `Ok`, при ошибке читайте `ErrorCode` и `ErrorDescription`.

```typescript
if (!kkm.Ok) {
    throw new Error(`${kkm.ErrorCode}: ${kkm.ErrorDescription}`);
}
```

Ограничения:

- один экземпляр `ServerKkm` не рассчитан на параллельные запросы к разным
  кассам одновременно — на параллельную работу создавайте отдельные экземпляры;
- коннектор не проверяет состав чека — неверные данные отвергнет сервер;
- после `dispose()` экземпляр использовать нельзя;
- текущий запрос можно прервать методом `kkm.cancel()`.

## Использование

Схема работы одна для всех операций: **задать свойства → вызвать метод →
прочитать результат из свойств**.

### Подключение

| Свойство | По умолчанию | Назначение |
| --- | --- | --- |
| `Host` | `localhost` | Хост сервера ККМ (IP или DNS) |
| `Port` | `4398` | TCP-порт службы печати |
| `UseHttps` | `false` | Обращаться к серверу по HTTPS вместо HTTP |
| `TimeoutMs` | `60000` | Таймаут запроса к серверу, мс |
| `Token` | пусто | Токен авторизации (заголовок `api_key`). Нужен, если на сервере выключен анонимный доступ |
| `AuthUserName` | `Admin` | Логин для `GetUserToken()` (Basic Auth) |
| `AuthPassword` | `Admin` | Пароль для `GetUserToken()` |
| `TerminalId` | пусто | Идентификатор рабочего места (заголовок `TerminalId`) |
| `DeviceName` | пусто | Имя кассы на сервере |
| `Cashier` | `undefined` | Кассир для документов |
| `QueueTaskId` | пусто | Id задания в очереди печати |
| `ShiftsFrom` / `ShiftsTo` | последние 7 дней | Период для списков отчётов, чеков и операций (строки `yyyy-MM-dd`) |

Токен берётся в веб-консоли сервера ККМ из профиля пользователя (или через
`GetUserToken()` по логину/паролю). `Ping()` работает и без токена. Хост, порт,
токен и имя кассы можно менять между вызовами — один экземпляр по очереди
работает с разными ККТ.

```typescript
await kkm.Ping();          // проверка связи
await kkm.GetDeviceList();  // список касс
await kkm.Connect();        // сведения по DeviceName
```

### Пример: печать чека прихода

```typescript
import { ServerKkm, Cashier, FiscalLine, Payments } from "skkmconnectorts";

const kkm = new ServerKkm();
kkm.Host = "localhost";
kkm.Token = "<токен>";
kkm.DeviceName = "Emu";

const cashier = new Cashier();
cashier.Name = "Иванов А.И.";
kkm.Cashier = cashier;

kkm.NewRequest();          // сброс позиций, оплат, покупателя
kkm.PaymentType = 1;       // тип чека
kkm.TaxVariant = 0;        // система налогообложения

const line = new FiscalLine();
line.Name = "Кофе американо";
line.PriceWithDiscount = 150;
line.SumWithDiscount = 150;
line.Tax = "20";
kkm.Positions.push(line);

const payments = new Payments();
payments.Cash = 150;
kkm.Payments = payments;

await kkm.PrintCheck();
if (!kkm.Ok) {
    throw new Error(`${kkm.ErrorCode}: ${kkm.ErrorDescription}`);
}

console.log(`ФП: ${kkm.FiscalSign}, смена: ${kkm.ShiftNumber}`);
```

Остальные операции устроены так же: смена (`OpenShift`, `CloseShift`, `ReportX`),
возврат и коррекция (тот же `PrintCheck` / методы `PrintCheckCorrection105`/`120`),
наличные (`CashIn`, `CashOut`), слип, картинки, маркировка, фискализация,
шаблоны, очередь, администрирование.

## Генерация HTML-справочника по коннектору
 
Помимо подсказок в IDE, из тех же JSDoc-комментариев можно собрать отдельный
HTML-справочник по всем классам, методам, входным моделям и перечислениям —
удобно, если документацию нужно посмотреть в браузере или отдать кому-то
отдельным файлом, без открытия IDE.
 
**Разовая настройка** (один раз в папке коннектора):
 
```bash
npm install --save-dev documentation --legacy-peer-deps
npm pkg set scripts.docs="npm run build && documentation build dist/index.d.ts -f html -o docs"
```
 
Вторая команда добавляет в `package.json` скрипт `docs` — дальше он уже
сохранён в проекте, повторять установку не нужно.
 
**Генерация** (каждый раз, когда нужна свежая версия):
 
```bash
npm run docs
```
 
Команда сначала пересобирает коннектор (`npm run build`), затем строит
HTML-справочник **из `.d.ts`** (не из `.ts` — поэтому сборка обязательна перед
генерацией) в папку `docs/`. Откройте `docs/index.html` в браузере — там
все классы (`ServerKkm`, DTO, перечисления), их поля и методы со всеми
JSDoc-описаниями, сгруппированные и с поиском.
 
> Собирать из `dist/index.d.ts`, а не из `src/`, важно: `.d.ts`-файлы уже
> содержат разрешённые типы и не путают `documentation.js` ESM-импортами
> с расширением `.js`, которые встречаются в исходниках.
